### 关键洞察

> **"The agent never waits -- work happens in background threads."**

主代理循环继续处理其他工作，后台任务在独立线程中执行，通过通知队列获取结果。

### S08 核心创新：线程级并发

#### 为什么需要后台任务？

- 有些命令执行时间很长（编译、测试、数据处理）
- S01-S07 的模式：代理等待命令完成才能继续
- 需要：**发起命令 -> 立即继续 -> 稍后获取结果**

#### 解决方案：守护线程 + 队列通知

```python
import threading
from queue import Queue

class BackgroundManager:
    def __init__(self):
        self.tasks = {}              # 任务状态记录
        self.notifications = Queue() # 通知队列

    def run(self, command: str, timeout: int = 120) -> str:
        tid = str(uuid.uuid4())[:8]
        self.tasks[tid] = {"status": "running", "command": command, "result": None}
        # 启动守护线程执行命令
        threading.Thread(target=self._exec, args=(tid, command, timeout), daemon=True).start()
        return f"Background task {tid} started"

    def _exec(self, tid, command, timeout):
        # 在后台线程中执行
        r = subprocess.run(command, shell=True, capture_output=True, text=True, timeout=timeout)
        self.tasks[tid].update({"status": "completed", "result": output})
        # 发送通知
        self.notifications.put({"task_id": tid, "status": "completed", "result": ...})
```

### 通知队列机制

#### `Queue` vs `list`

| 特性 | `list` | `Queue` |
|------|--------|---------|
| 线程安全 | ❌ | ✅ |
| 阻塞等待 | ❌ | ✅ |
| 用途 | 普通列表 | 生产者/消费者 |

```python
from queue import Queue

q = Queue()

# 生产者
q.put({"task_id": "abc", "result": "done"})

# 消费者
item = q.get()  # 有数据则返回，无数据则阻塞
item = q.get_nowait()  # 非阻塞版本

# 检查是否为空
q.empty()  # True/False
q.qsize() # 队列大小
```

### drain() 模式

`drain()` 的设计很有意思——它一次性抽取所有待处理的通知：

```python
def drain(self) -> list:
    """抽取并返回所有待处理通知"""
    notifs = []
    while not self.notifications.empty():
        notifs.append(self.notifications.get_nowait())
    return notifs
```

为什么不逐个处理？因为：

1. 每轮主循环只调用一次 `drain()`
2. 一次抽取全部，避免遗漏
3. 批量注入上下文，减少消息数量

### 错误处理

```python
def _exec(self, tid, command, timeout):
    try:
        r = subprocess.run(command, ...)
        output = (r.stdout + r.stderr).strip()[:50000]
        self.tasks[tid].update({
            "status": "completed",
            "result": output or "(no output)"
        })
    except subprocess.TimeoutExpired:
        self.tasks[tid].update({
            "status": "error",
            "result": "Error: Timeout (120s)"
        })
    except Exception as e:
        self.tasks[tid].update({
            "status": "error",
            "result": str(e)
        })
    # 无论成功失败都发送通知
    self.notifications.put({...})
```

### 核心模式

```
启动：background_run(command, timeout=120)
    ↓
立即返回 task_id，主循环继续
    ↓
工作完成后通知写入队列
    ↓
主循环调用 drain() 获取所有通知
    ↓
通知注入 <background-results> 标签
```

### 守护线程特性

```python
threading.Thread(target=..., daemon=True)
```

守护线程的特点：

- 优点：主程序退出时自动终止，不阻塞
- 缺点：正在执行的任务会被强制终止

对于长时间运行的后台任务，应该使用非守护线程或确保任务能在合理时间内完成。
